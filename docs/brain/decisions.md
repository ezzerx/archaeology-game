# Décisions initiales

Source : demande confirmée d’Antoine du 2026-09-30. Ces décisions cadrent la préproduction ; elles ne constituent pas des résultats de playtest.

| Décision | Raison / conséquence |
|---|---|
| Canoniser avant de développer | Conserver une référence claire et portable ; aucune implémentation dans cette étape |
| ArchaeologyGame comme working title neutre | Permettre l’initialisation sans figer le nom commercial |
| Dépôt GitHub privé par défaut | Conserver le brainstorming dans le compte d’Antoine |
| Tabletop strictement du dessus, sans personnage ni monde ouvert | Concentrer l’expérience sur les gestes de fouille et la découverte |
| Game feel prioritaire | Tester résistance, réactions, son et rythme avant le volume de contenu |
| Musée horizontal et squelettes réellement incomplets | Rendre l’acquisition de fragments tangible et motivante |
| Prototype v0.1 minimal | Un écran, bloc, fossile ; trois matériaux / outils ; aucune production étendue |
| DA à décider après un prototype joué | Vérifier la compatibilité du pixel art avec l’effacement libre ; comparer une 2D illustrée |
| Godot envisagé, version non fixée | Vérifier les capacités et la version stable au début du développement |
| Brain canonique dans le dépôt | Reprendre depuis un autre PC sans dépendre de la mémoire globale ; celle-ci ne stocke qu’un pointeur |

## Propositions encore ouvertes

La sélection terre / argile / grès et soft brush / chisel / blower est un point de départ de v0.1. Fragilité, résine, seuils d’identification, quantités de pièces, catégories du musée et statistiques supplémentaires attendent un test ou une décision explicite.

Ne pas présenter ces hypothèses comme validées ni convertir les exemples de compteurs en anatomie canonique.
