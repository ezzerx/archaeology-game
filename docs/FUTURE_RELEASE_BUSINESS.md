# Future Release / Studio Notes

**Status:** product/business context only. Not an active development phase.

## Commercial studio identity

Antoine prefers, if the game proves itself, to create a **commercial studio brand** around the project before necessarily creating a separate legal company.

Intent:
- give the game and future projects a credible public developer identity;
- make the project stronger on CV / LinkedIn than a generic “created archaeology game” line;
- reuse reputation/traction from a successful first release for later game projects.

A dedicated legal entity is **not** required merely to create the studio brand. Legal/tax structure should be revisited only when release/revenue/spend makes it useful.

## Career value

If the project reaches a credible shipped state, it should be presented as evidence of:
- product ownership;
- game/product design;
- technical orchestration;
- user testing / iteration;
- visual direction and production pipeline;
- release/Steam execution;
- end-to-end indie product delivery.

The value is the shipped, validated product and documented decision process, not just the project name.

## Steam later-phase checklist

A later release phase should cover:
- Steamworks onboarding / Steam Direct;
- store page, branding, screenshots, trailer, tags, localization and pricing;
- demo / Steam Playtest / Next Fest strategy where useful;
- production build settings, saves, input, crash handling, versioning;
- content survey / required disclosures;
- QA / review submission;
- patching/community/post-launch operations.

Do not pull Steam/release work into P6A geometry/lookdev.

## Product-market sequencing

Current principle:
> first make a game players genuinely enjoy and trust the core quality; only then optimize positioning, virality and launch-market angle.

No commercial launch promise or sales target is treated as a development requirement at this stage.
